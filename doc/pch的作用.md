# PCH 的作用
## 1. 没有 pch 会咋样
如果没有 pch ，每个编译单元 include 进来的头文件，最后编译的时候都会完整再走一遍词法分析，生成 AST。试想一下你导入 `windows.h` 这一坨大的。编译时间直接给你拉爆了。
pch 的时候就是把你常用的，固定不变的头文件，提前 include 进去，解析好，然后 Dump 为一个 .pch 二进制文件。有点预处理的味道在里面，使用 cmake 提供的 `target_precompile_headers` 功能，它会在每个编译单元前面隐式加上 `-include "pch.h"`，然后编译器一看到这个，就会把 .pch 里面的数据 Dedump 回来，不用再走一遍词法分析。
## 2. 最佳实践
由于 cmake 帮我们做了隐式的 `-include "pch.h`，所以我们不用自己去 include 它了。但是我们在 pch 里面 include 的文件，比如 vector 和 string，虽然词法分析已经分析好了，理论上来说我们自己的文件里连 `#include <vector>` 也不用写了，但最好还是写上。
为什么呢？因为 pch 依托于你的构建状态，而且可能经常修改对吧。 C++ 编程里有一条范式就是 “IWYU (Include What You Use)”。
假如某天把代码移植到一个不支持 PCH 的平台，或者某人把 cmake 里的 pch 选项注释掉了。那我们现在的这些代码就全部炸缸了。
说到底就是没有一个所谓的 “回退” 操作，或者说兜底操作。
所以我们自己编程的时候最好还是加上 “include”，因为编译器读到 `#include "pch.h"` 之后就会跳过那些已经载入的头文件了。所以依旧会起到加速的作用。
